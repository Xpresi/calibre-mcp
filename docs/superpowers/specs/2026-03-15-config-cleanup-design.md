# Design: Configuration Cleanup & Repository Hygiene

**Date:** 2026-03-15
**Status:** Approved
**Scope:** Make calibre-mcp shareable by removing personal paths from the repo

---

## Problem

The repository contains personal filesystem paths in two places:

1. `config.json` (not gitignored) — has real path `D:\archivos\Libros\Calibre Library`
2. `config.py` — `library_path` default is a personal path; `calibredb_path` default is the standard Windows install path (safe to keep)
3. `README.md` — config example shows the personal library path

Additionally:
- No `.gitignore` exists, and `__pycache__/` + `*.pyc` files are already tracked in git
- Version mismatch: `pyproject.toml` says `0.1.0`, `server.py` says `0.2.0`

---

## Approach: Full Cleanup (Option B)

Keep `config.json` local and gitignored. Provide a `config.json.example` template. No environment variables (can be added later).

---

## Section 1: Configuration

### `config.py`
- `library_path` default: personal path `D:\archivos\Libros\Calibre Library` → `""`
- `calibredb_path` default: `C:\Program Files\Calibre2\calibredb.exe` — **keep as-is** (standard Windows install path, not personal, improves out-of-box experience for Windows users)
- No other logic changes
- Note: `Path("").exists()` returns `False` on Windows/Linux/macOS (verified), so `validate()` will produce clear errors like `"Library path not found: "` without raising exceptions

### `config.json`
- File content unchanged (user's real paths stay, it works locally)
- Added to `.gitignore` so it never enters the repo

### `config.json.example` (new file)
Content uses the real `calibredb_path` default (standard path) and a clearly labeled placeholder for `library_path`:

```json
{
    "calibredb_path": "C:\\Program Files\\Calibre2\\calibredb.exe",
    "library_path": "C:\\Users\\YourName\\Calibre Library",
    "backup_before_bulk_ops": true,
    "dry_run_by_default": true
}
```

Note: On Linux/macOS, `calibredb_path` is typically `/usr/bin/calibredb`. This is documented in the README.

## Section 2: Repository Hygiene

### `.gitignore` (new file)

```gitignore
# Personal configuration — copy config.json.example → config.json and edit
config.json

# Python
__pycache__/
*.pyc
*.pyo
*.pyd

# Virtual environments
.venv/
venv/
env/

# Build & distribution
dist/
build/
*.egg-info/

# Testing
.pytest_cache/
.coverage
htmlcov/

# Database backups generated by backup_database tool
metadata_backup_*.db
```

**Important:** After creating `.gitignore`, run `git rm -r --cached` on already-tracked `__pycache__/` directories and `*.pyc` files so git stops tracking them. These are already present in the repo.

### `pyproject.toml`
- Version: `0.1.0` → `0.2.0` (matches `server.py`)

### `README.md`
Three changes:

1. **Config example**: Replace `D:\\archivos\\Libros\\Calibre Library` with `C:\\Users\\YourName\\Calibre Library` (consistent with `config.json.example`)
2. **Architecture note**: "Platform: Windows" → "Primary platform: Windows; calibredb also available on Linux/macOS (calibredb path is typically `/usr/bin/calibredb`)"
3. **Getting Started paragraph** (add before "## Configuration"):
   > Copy `config.json.example` to `config.json` and edit it with your paths. The `config.json` file is gitignored and will not be committed.

4. **Tools list**: Out of scope for this change — the README tools list is known to be incomplete relative to `server.py`. This will be addressed in a separate task.

## Git cleanup step (one-time)

After creating `.gitignore`:
```bash
git rm -r --cached "src/calibre_mcp/__pycache__"
git rm -r --cached "src/calibre_mcp/tools/__pycache__"
git rm -r --cached "src/calibre_mcp/utils/__pycache__"
git rm -r --cached "tests/__pycache__" 2>/dev/null || true
```

- All tool logic: backend, query/write/bulk/report modules
- `Config.load()` search order
- `Config.validate()` error messages
- MCP server entry point and tool registration
- `calibredb_path` default value (kept as standard Windows path)
